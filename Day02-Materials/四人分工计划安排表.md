# Day02 八个机器学习算法任务 — 四人分工计划安排表

> 项目：8 个机器学习算法任务（10 个 Notebook）+ 环境搭建 + 数据准备 + 测试验证 + 文档交付
> 团队规模：4 人 ｜ 总工期：3.5 天（可按半天为粒度压缩至 2 天）

---

## 一、角色与职责总览

| 成员 | 角色 | 职责范围 | 负责任务 |
|------|------|----------|----------|
| 成员A | 组长 / 环境与数据工程 / 模型评估 | 项目排期、开发环境统一、外部数据获取、兼容性适配决策、模型评估模块、最终验收与打包 | 任务8.1、任务8.2 |
| 成员B | 监督学习-分类方向开发 | KNN 与逻辑回归两个算法族的全部分类任务，含可视化 | 任务1、任务2、任务4 |
| 成员C | 监督学习-回归方向开发 | 线性回归 / Ridge / 决策树与集成算法，含数据集兼容性适配与外部数据接入 | 任务3、任务5 |
| 成员D | 无监督学习方向开发 | 聚类（Birch/KMeans/DBSCAN）与降维（PCA/LDA）任务，含调参实验 | 任务6.1、任务6.2、任务7 |

> 姓名可替换为真实成员姓名；A 的管理类工作（环境/数据/验收）与 2 个开发任务工作量合计与其他成员相当。

## 二、按开发流程的阶段安排

### 阶段① 需求分析与环境搭建（第 1 天上午，全员）

| 工作项 | 负责人 | 产出物 |
|--------|--------|--------|
| 通读 8 份任务书 PDF，拆解 10 个 Notebook 的交付标准，确认评分口径 | 全员（A 主持） | 任务清单与排期表 |
| 创建 `.venv` 虚拟环境（Python 3.14），安装 numpy/pandas/scikit-learn/matplotlib/ipykernel，配置国内镜像 | 成员A | 可运行环境 + 依赖清单 |
| 统一编码规范：`random_state=0` 固定随机种子、Notebook 首 cell 统一中文字体配置、命名与目录结构遵循 `DayXX-主题/章节` 规则 | 成员A | 开发约定文档（README 草稿） |
| 数据可用性预检：逐个确认 10 个任务的数据来源（内置数据集 / 在线 URL / 本地文件） | 成员C | 数据来源清单 |

### 阶段② 数据准备与兼容性适配（第 1 天下午，A+C 协作）

| 工作项 | 负责人 | 产出物 |
|--------|--------|--------|
| `load_boston` 在 sklearn≥1.2 已移除 → 选型并验证替代方案，确定 `fetch_openml(name="boston")` 加载同一份 506×13 原版数据 | 成员C（A 复核） | 任务3 数据加载方案（含代码注释） |
| OpenML 拉取 boston 数据并缓存到本地，验证离线可跑 | 成员A | 本地缓存 |
| 从 UCI 下载 `abalone.data`（4176 条）到「05 决策树」目录，校验行数与格式 | 成员C | abalone.data |
| sklearn 1.9 API 变更排查：KMeans `n_init` 显式传参、`LogisticRegression(penalty=)` 弃用预警 | 成员A | API 适配结论（同步全员） |

### 阶段③ 并行开发（第 2 天 ～ 第 3 天上午，按算法线并行）

| 任务 | 内容要点 | 负责人 | 预估工时 |
|------|----------|--------|----------|
| 任务1 | 鸢尾花 KNN：数据探索 → DataFrame → 散点图 → 划分 → 建模（K=3）→ 预测新样本 | 成员B | 2h |
| 任务2 | 红酒 KNN：13 特征探索 → 10 组随机特征散点图 → 建模评估，分析未标准化对得分的影响 | 成员B | 2h |
| 任务4 | 逻辑回归肿瘤预测：cancer 建模评估 + predict/proba 对比 + iris 调参（C、penalty） | 成员B | 2h |
| 任务3 | 线性回归房价预测：适配后的 boston 数据 → LinearRegression/Ridge 建模 → 预测对比曲线 | 成员C | 2h |
| 任务5 | 决策树与集成：鲍鱼年龄回归 + 肿瘤分类四模型对比（无剪枝/剪枝/随机森林/AdaBoost） | 成员C | 3h |
| 任务6.1 | 多算法聚类：一维 Birch/KMeans 演示 → make_blobs 四簇 → 鸢尾花聚类 ARI 评估与双图对比 | 成员D | 3h |
| 任务6.2 | DBSCAN 环形数据：构造内中外三圈数据 → 验证传统方法失效 → eps/min_samples 网格调参 | 成员D | 2h |
| 任务7 | PCA/LDA 降维：iris KNN 降维前后对比 → wine 双方法可视化 → LDA 降维后 LR 评估 | 成员D | 2h |
| 任务8.1 | 交叉验证：3 折 / 留一法（150 折）/ ShuffleSplit 两种模式 | 成员A | 1.5h |
| 任务8.2 | ROC 与 P-R 曲线：SVC 三种核 ROC 对比（AUC）+ 逻辑回归 P-R 曲线 | 成员A | 2h |

> 并行原则：B/C/D 三条算法线互不依赖，可完全并行；A 在完成评估线开发的同时负责答疑与进度同步（每日站会 15min）。

### 阶段④ 交叉测试与联调（第 3 天下午，全员交叉）

| 工作项 | 负责人 | 验收标准 |
|--------|--------|----------|
| 交叉重跑：B↔C 互换、A↔D 互换，从零重跑对方全部 Notebook | B、C、A、D | 无报错、无残留 `?` 占位符、图表正常渲染 |
| 结果比对：核对各模型得分与经典教材/任务书参考值是否一致（如 iris KNN≈0.97、boston R²≈0.64、随机森林 0.97） | 全员 | 偏差在随机种子可解释范围内 |
| 可复现性验证：清理输出后全量重跑，确认 `random_state` 固定后结果一致 | 成员A | 两次运行输出一致 |
| 问题回修：测试发现的问题回溯到原开发人修复，修复后重新交叉验证 | 各原开发人 | 缺陷清零 |
