# 团队分工计划安排表

项目：训练任务 3「问答助手」—— 基于 OpenAI Agents SDK 的简单智能体
团队规模：4 人 | 开发周期：7 个工作日（Day1–Day7，可映射到实际日期）
代码库：`qa-agent/`（Python 3.14，src 布局，38 个 pytest 单测，PyInstaller 发布 exe）

---

## 1. 角色总览

| 成员 | 角色 | 工作量占比 | 核心职责 |
|------|------|-----------|---------|
| **成员 A** | 组长 / 架构师 | ~20% | 需求分析、技术选型、总体架构与接口约定、集成联调、技术文档汇总 |
| **成员 B** | 智能体与交互开发 | ~30% | 配置体系、Agent 层（系统提示词）、CLI 多轮对话、LLM 接口对接与推理模型适配 |
| **成员 C** | 工具层开发 | ~25% | 计算器工具（安全求值）、联网搜索（Tavily + DuckDuckGo 双后端降级链）、搜索 API 集成 |
| **成员 D** | 测试 / 打包 / 发布 | ~25% | pytest 测试体系、冒烟与自检工具、PyInstaller 打包、发布包制作、验收 |

## 2. 四人分工总表（按模块对齐代码库）

| 代码模块 | 负责人 | 关键交付物 | 设计要点（答辩叙述口径） |

| `__main__.py`（CLI） | B | 多轮循环（`to_input_list()` 维护历史）、流式输出（过滤 `reasoning_summary` 事件）、`/reset` `/quit`、`--check` 连通自检 | Runner 无状态，历史由调用方维护；推理模型思考内容不外显 |

| PyInstaller 打包 | D | `launcher.py`、`qa-agent.spec`、三坑修复（mcp 元数据 / agents 数据文件 / stdio 编码容错）、发布包 `问答助手-win64.zip` | 冻结模式读 exe 同目录 `.env`；发布物断言无真实 Key |

## 3. 开发时序安排（Day × 成员矩阵）

> 顺序与本项目实际开发流程一致：选型 → 脚手架/配置 → 工具层与智能体层并行 → CLI → 联调攻坚 → 测试打包 → 验收。

| 阶段 | 成员 A（架构） | 成员 B（智能体/交互） | 成员 C（工具层） | 成员 D（测试/打包） |
|------|--------------|---------------------|-----------------|-------------------|
| **Day1** 需求与预研 | 主持需求分析，确定"问答助手"方向；输出选型调研（4 框架 + 2 搜索后端 + 网络环境评估） | 预研 Agents SDK（Agent/Runner/FunctionTool 概念） | 预研 Tavily REST 与 ddgs 的参数、返回结构、额度规则 | 预研 pytest mock 方案与 PyInstaller 可行性 |
| **Day2** 脚手架与约定 | 产出架构图 + 接口约定（`Settings` 字段、工具签名、降级链设计），组织评审 | `pyproject.toml`、`.env` 体系、`config.py`（含占位 Key 校验） | `calculator.py`：AST 白名单求值 + 三层防御 | 搭 pytest 骨架，定 mock 约定（不发起真实网络） |
| **Day3** 核心并行 | 评审系统提示词草案；跟踪接口对接 | `agent.py`：Chat Completions 显式接入、系统提示词、`--check` 自检 | `internet_search.py`：Tavily 后端 + Key 注入 | `test_calculator.py`、`test_config.py` 用例编写 |
| **Day4** 交互与降级 | 日检进度，协调 B/C 联调时间点 | `__main__.py`：多轮历史、流式输出、对话命令 | ddgs 兜底 + 降级链（附降级原因） + 结果格式化 | `test_internet_search.py`（含降级链用例）、`smoke_search.py` |
| **Day5** **联调攻坚**（全员） | 主持联调；定位"模型声称没有搜索工具"根因（工具名与智谱内置 `web_search` 重名被拦截 → 全员评审更名 `internet_search`） | 适配推理模型：`--check` max_tokens 提至 512；流式过滤思考事件 | 排查搜索静默降级（工具内补 `load_env()`）；原始 API 最小复现验证 | 每修一坑补回归测试；维护踩坑记录（进技术文档） |
| **Day6** 测试收尾与打包 | 汇总技术文档（设计决策 + 评分对照） | 补模块文档与 README 使用说明 | 补工具设计文档（安全求值论证） | 38 用例收尾全绿；PyInstaller 打包（mcp 元数据、agents 数据文件、编码容错三坑）；制作发布 zip |
| **Day7** 验收发布 | 组织验收：对照评分标准逐项自查 | 演示：多轮对话 + 计算器 + 搜索带来源 | 演示：搜索降级链与防注入拒绝路径 | `--check`/单测/发布包三项验证；zip 无 Key 泄漏断言 |

里程碑：Day2 末接口冻结 → Day4 末功能完整可跑 → Day5 末坑清零 → Day6 末发布包就绪 → Day7 验收。

## 4. 协作机制

1. **接口先行**：Day2 末冻结 `Settings` 字段与工具函数签名，B/C 依约并行开发，互不阻塞。
2. **模块边界**：工具层不依赖 CLI/Agent 层（仅依赖 `config.load_env`），保证可独立测试。
3. **每日 15 分钟站会**：同步进度与阻塞；Day5 联调期改为早晚两次。
4. **分支模型**：`main`（可发布）/ `dev`（集成）/ `feature/<模块>`（个人）；合并走 PR + 一人交叉评审。
5. **踩坑登记**：任何"静默失败"类问题（如工具重名拦截）必须先最小复现、再修复、再补回归测试，全程记录进技术文档。

## 5. 风险与应对

| 风险 | 影响 | 应对（本项目已验证） |
|------|------|---------------------|
| 国内网络：PyPI 直连拿不到版本、DuckDuckGo 超时 | 依赖装不上、搜索不可用 | pip/uv 强制清华镜像；Tavily 为主搜索（可直连），ddgs 仅兜底 |
| 供应商差异：内置工具重名、Responses API 不兼容 | 工具静默失效、请求报错 | 显式 Chat Completions 模型类；工具命名避开内置名；`--check` 快速隔离问题层 |
| 推理模型行为（思考耗 token、思考外显） | 空回复、输出混乱 | max_tokens 预算放宽；流式事件按类型过滤 |
| API Key 泄漏 | 额度被盗用 | `.env` 入 `.gitignore`；发布物只含 `.env.example`，打包脚本断言校验 |
| exe 打包失败（动态导入/元数据/数据文件） | 无法交付绿色版 | 踩坑清单固化进技术文档；spec 文件可一键复现 |
