## 1. 项目概述

本智能体基于 **OpenAI Agents SDK** 实现「问答助手」：以大模型为核心对话与推理引擎，
通过 Function Calling 机制挂载两类工具（计算器、联网搜索），在 CLI 中提供多轮流式对话。

核心行为模式：

- 用户提问涉及**数学计算** → 模型自动调用 `calculator`，不心算
- 用户提问涉及**时效性/不确定事实** → 模型自动调用 `internet_search`（Tavily），回答附来源链接
- **一般知识问题** → 直接回答，不浪费工具调用

目标：演示"简单智能体"的完整三要素——**模型推理 + 工具调用 + 编排循环**，
且全部配置（模型接口、API Key、搜索后端）由 `.env` 驱动，零代码改动可切换供应商。

## 3. 架构设计

### 3.1 架构图

```
┌────────────────────────────────────────────────┐
│              CLI（__main__.py）                  │
│  多轮循环 · 流式输出(过滤思考) · /reset /quit · --check │
└──────────────────┬─────────────────────────────┘
                   │ Runner.run_streamed(agent, history+[新消息], max_turns=8)
                   ▼
┌────────────────────────────────────────────────┐
│           Agent（agent.py）「问答助手」            │
│  instructions：中文系统提示（行为规范）             │
│  model：OpenAIChatCompletionsModel              │
│         └→ AsyncOpenAI(base_url, api_key)       │
│  tools：[calculator, internet_search]           │
└───────┬────────────────────────┬───────────────┘
        │ Function Calling        │ Function Calling
        ▼                         ▼
┌──────────────────┐   ┌───────────────────────────┐
│ calculator        │   │ internet_search            │
│ AST 白名单求值     │   │ ├─ 有Key: Tavily REST      │
│ 防注入/防指数爆炸   │   │ │  (httpx, 国内直连)        │
│                   │   │ └─ 无Key/失败: ddgs 兜底    │
└──────────────────┘   └───────────────────────────┘

配置层（config.py）：.env → Settings(base_url, api_key, model, tavily_api_key)
```

### 3.2 一次工具调用的完整时序

以用户问"帮我算一下 (128+72)\*3^2，再搜一下智谱GLM最新模型"为例：

```
用户输入
  │
  ├─► CLI: history + {"role":"user","content":...} 传给 Runner.run_streamed
  │
  ├─► SDK: 组装 messages（instructions 转为 system 消息 + tools 的 JSON Schema）
  │    发往 POST {base_url}/chat/completions
  │
  ├─► 模型返回 tool_calls: [calculator("(128+72)*3^2"),           ← 第1轮
  │                         internet_search("智谱GLM最新模型")]
  │    （两个工具无依赖，模型并行发出）
  │
  ├─► SDK: 本地执行两个 Python 函数
  │    ├─ calculator: ast.parse → 白名单遍历求值 → "1800"
  │    └─ internet_search: 读 TAVILY_API_KEY → httpx POST tavily
  │         → 格式化 标题+链接+摘要 → 返回文本
  │
  ├─► SDK: 工具结果以 role="tool" 消息追加，再次请求模型          ← 第2轮
  │
  ├─► 模型综合工具结果生成最终回答（流式）
  │    └─ CLI 只打印 response.output_text.delta，思考内容不显示
  │
  └─► CLI: history = result.to_input_list()   ← 含工具调用记录的完整历史
       （下一轮带上，模型能"看见"上轮调了什么工具、得到什么结果）
```

## 4. 关键设计决策（含踩坑记录）

### 4.1 显式使用 Chat Completions 模型类

Agents SDK 默认走 OpenAI 官方 **Responses API**，而第三方兼容端点
（智谱中转、DeepSeek、通义、Ollama 等）通常只实现 Chat Completions。
因此 `agent.py` 显式构造：

```python
from agents.models.openai_chatcompletions import OpenAIChatCompletionsModel

client = AsyncOpenAI(base_url=settings.base_url, api_key=settings.api_key)
model = OpenAIChatCompletionsModel(model=settings.model, openai_client=client)
```

配套 `set_tracing_disabled(True)`：trace 上传依赖 OpenAI 官方端点，自定义端点必须关闭，否则每次运行告警。

### 4.2 多轮会话：调用方维护历史

SDK 的 `Runner` 是**无状态**的。CLI 在循环外维护 `history` 列表：

```python
result = Runner.run_streamed(agent, input=history + [{"role": "user", "content": user_input}], max_turns=8)
...
history = result.to_input_list()   # 取回含工具调用记录的完整历史
```

关键点：`to_input_list()` 返回的历史**包含工具调用与工具结果消息**，模型下一轮能
"看见"自己上轮调过什么工具、得到什么结果——这是多轮推理连贯的前提。
`/reset` 只清空列表，Agent 对象复用。`max_turns=8` 限制单轮对话内
"模型↔工具"的最大往返次数，防止异常模型陷入无限工具循环。

### 4.3 计算器：AST 白名单求值，不用 eval

直接 `eval()` 用户表达式是注入漏洞（`__import__('os').system(...)`）。
实现分三层防御：

1. **语法层**：`ast.parse(expr, mode="eval")`，非法表达式直接拒绝
2. **节点白名单**：递归遍历语法树，只允许
   `BinOp`(加减乘除/整除/取模/幂)、`UnaryOp`(正负号)、`Constant`(数字)、
   `Name`(仅 `pi`/`e`)——函数调用、属性访问、下标等一切其他节点抛 `ExpressionError`
3. **资源护栏**：表达式长度 ≤ 200；幂指数绝对值 ≤ 1000（防 `9**9**9` 合法但爆炸）

另外 `^` 自动转 `**`（用户习惯兼容）；整数浮点结果规范化（`4/2` → `"2"`）；
错误（语法错误/除零/溢出）以中文文本字符串返回给模型，由模型向用户解释，
**绝不让异常炸掉整轮对话**。

### 4.4 搜索：双后端降级链 + 异常就地消化

```
_do_search(query)
  ├─ 读 TAVILY_API_KEY（工具内自带 load_dotenv()，见 4.6）
  ├─ 有 Key ──► _tavily_search()   成功 → 返回
  │               └─ 失败 ──► _ddgs_search() + 注明降级原因   ← 可观测
  └─ 无 Key ──► _ddgs_search() 直接兜底
双后端都失败 → 返回 "搜索失败：异常类型: 原因" 文本给模型
```

设计考量：

- **Tavily 优先**：为 LLM 检索设计（结构化 `title/url/content/score` + `answer` 综合回答字段），国内直连
- **降级注明原因**：回退结果前附加"（提示：Tavily 搜索失败已自动回退…）"，行为可观测、便于排障
- **结果统一格式**：`序号. 标题 / 链接: URL / 摘要`，系统提示要求模型回答末尾注明来源链接

### 4.5 工具命名必须避开上游内置工具名（重要踩坑）

搜索工具最初命名为 `web_search`，接 glm-5.3-flash 时模型始终回答
"我只有计算器工具"，但代码里明明注册了两个工具。

**排查路径**（可复用的排障方法）：
SDK 层检查（`agent.tools` 确认注册）→ 原始 Chat Completions 请求最小复现
（只带那一个工具发请求）→ 确认与 SDK 无关 → 改名对照实验。

**根因**：智谱 API 存在同名**内置工具类型** `web_search`，上游在 tools 数组
里把重名的函数工具静默拦截，模型根本看不到它。改名 `internet_search` 后
立即正常（还会并行发多个搜索请求）。

**推广结论**：函数工具命名应避开各家供应商的内置工具名
（`web_search`、`code_interpreter`、`retrieval`、`function_call` 等）。
此坑无任何报错，纯静默失败，已写入工具源码注释。

### 4.6 工具代码自带 load_dotenv()

工具函数可能脱离主入口被独立调用（`smoke_search.py` 冒烟脚本、单测），
不能假设主程序已加载 `.env`。`_do_search()` 内部调用幂等的 `load_dotenv()`，
开销可忽略。教训来自一次真实 bug：重写工具时丢了这行，冒烟脚本读不到
Tavily Key，静默降级到 DuckDuckGo 后超时。

### 4.7 推理模型（glm-5.3-flash）的两个适配点

glm-5.3-flash 是推理模型，先输出思考（`reasoning_content`）再输出正文：

1. **max_tokens 必须给足**：思考内容也消耗 token 配额。`--check` 最初给
   `max_tokens=8`，全部被思考消耗，`finish_reason=stop` 但正文为空。改为 512。
2. **流式输出过滤思考**：流式事件中思考内容是
   `response.reasoning_summary_text.delta`，正文是 `response.output_text.delta`。
   CLI 只打印后者，用户看不到大段英文思考过程。

### 4.8 工具行为规范写在系统提示中

`instructions` 明确约定（对应评分"设计合理性"）：

```
2. 遇到数学计算（哪怕很简单）时，调用 calculator 工具，不要心算。     ← 保证计算准确
3. 遇到时效性问题…调用 internet_search 工具查证，并在回答末尾注明信息来源链接。 ← 可溯源
4. 一般知识问题直接回答，不必每次都调用工具。                          ← 不浪费调用
```

工具该用时用、不该用时不滥用——这是工具调用智能体设计的核心权衡。

- SDK 的 `on_invoke_tool` 需要真实 `ToolContext`（`context=None` 会

  （`ToolContext` 继承 `RunContextWrapper`，SDK 内部会读 `ctx.tool_name` 等字段）
- 工具返回值是 JSON 编码的字符串，测试用 `json.loads` 解包

## 8. 打包分发（Windows exe，PyInstaller）

发布物：`release/问答助手-win64.zip`（exe + .env.example + 使用说明.txt），
接收方无需 Python，填好 `.env` 即用；构建命令（spec 文件 `qa-agent.spec` 已固化）：

```bash
.venv/Scripts/python -m PyInstaller --noconfirm --clean --onefile --console \
  --name qa-agent \
  --copy-metadata mcp --copy-metadata mcp-types \
  --copy-metadata openai-agents --copy-metadata openai --copy-metadata ddgs \
  --collect-data agents --collect-data mcp \
  launcher.py
```

实测踩过的三个坑（换机器构建失败时按此排查）：

| 报错 | 原因 | 修复 |
|------|------|------|
| `PackageNotFoundError: mcp` | agents SDK 用 `importlib.metadata` 探测 mcp 版本，PyInstaller 不收集包元数据 | `--copy-metadata mcp`（连 mcp-types/openai*/ddgs 一起带上） |
| `FileNotFoundError: ...agents\sandbox\memory\prompts\*.md` | agents 包内自带提示词数据文件未收集 | `--collect-data agents --collect-data mcp` |
| 对话报 `UnicodeEncodeError ... surrogates not allowed` | 管道输入编码不一致产生 surrogate 字符进入请求体 | `launcher.py` 对 stdin/stdout/stderr 统一 `reconfigure(errors="replace")`；真实控制台输入走 ReadConsoleW 本就不受影响 |

配套改动：

- **冻结模式读 .env**：`config.load_env()` 在 `sys.frozen` 时从 **exe 同目录** 读
  `.env`（源码模式维持 dotenv 默认搜索），否则 exe 在临时目录运行找不到配置
- **launcher.py**：打包专用入口，处理 stdio 编码容错
- **发布安全**：zip 中只有 `.env.example`（占位符），真实 `.env` 绝不进入发布物；
  打包脚本最后有断言校验
