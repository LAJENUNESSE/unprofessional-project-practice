## 2. 分工设计原则

分工对齐图像标注实验的实际工作流，拆成四条真实工作线：

1. **环境先行、风险前置**（LabelImg 是老项目，Python 3.14 兼容性是最大不确定点；`pyrcc5` 资源编译漏做即报 `No module named 'libs.resources'`）→ 环境工程线独立，对应成员D
2. **数据与标注规范是数据集质量的根**（选图要覆盖多类别/多目标/截断边缘等检测场景；框要贴目标边界）→ 数据与标注线，对应成员B
3. **标注执行与规范反馈分离**（标的人才知道规范哪里不合理，如 truncated 的界定）→ 标注操作线，对应成员C
4. **验证独立于标注**（框对不对不能由标注人自证；用离屏渲染脚本批量截图才是可复现证据）→ 质检验收线归组长，对应成员A

## 7. 协作机制

**接口约定（成员B → 成员A/C 的交接面）**：

- `make_annotations.py` 的 `ANNOTATIONS` 字典：框坐标唯一数据源，标注复核与后续修改都改这里再重新生成，不手改 XML
- `test/<同名>.xml` 命名约定：与图片同名同目录，这是 LabelImg 自动加载 XML 的前提
- 约定生效方式：成员C 基于 LabelImg 加载行为验收，素材/XML 变更须在群里同步

**日常协作规则**：

1. **风险前置原则**：老项目 × 新 Python 的组合先做兼容性冒烟（阶段1 实测 PyQt5 可用后才全面铺开）
2. **验收前移**：每阶段产物由组长按第 6 节标准验收后才进入下一阶段；渲染验证发现的重复框问题当阶段回溯修复
3. **可复现优先**：标注不留在"手工黑盒"里——框坐标进脚本、验证用离屏渲染截图、环境问题记录进错误对照表，三者都可重放
4. **文档即交付**：《实验说明.md》与实验同步成文，验证截图作为文档附件，不事后补写
