## 2. 分工设计原则

分工不是平均切块，而是对齐项目实际开发流程中的四条真实工作线：

1. **逻辑与界面分离**（项目核心架构决策）→ 天然形成"核心逻辑"与"GUI"两条线，对应成员B、成员C
2. **风险前置**（先做 PyInstaller 冒烟打包验证 Python 3.14 兼容性，再写业务代码）→ 工程化工作线独立前置，对应成员D
3. **测试与验收独立**（AI 测试全绿 ≠ 数据正确，样例"假重复行"靠人工验收发现）→ 验收职责归组长，对应成员A
4. **文档与演示是评分交付物**（占 AI 协作 30% 分数的呈现载体）→ 独立工作线，对应成员D

## 7. 协作机制

**接口约定（成员B → 成员C 的交接面）**：

- `Cleaner` 类：持有 DataFrame 与操作日志，GUI 只调用其方法、不直接改数据
- `InspectionReport` 数据类：体检结果结构化输出，GUI 的体检页直接渲染 `to_lines()`
- 约定生效方式：成员C 基于 core 的公开签名开发，core 变更须在群里同步

**日常协作规则**：

1. **风险前置原则**：任何新依赖、新环境变更先由成员D做冒烟验证再全员使用（本次 PyInstaller × Python 3.14 即受益于此）
2. **验收前移**：每阶段产物由组长按第 6 节标准验收后才进入下一阶段；验收发现的问题（如假重复行）退回责任成员当阶段修复
3. **测试守门**：core 层改动必须附 pytest 用例；GUI 层改动必须真机截图验证
4. **文档即交付**：文档与代码同阶段完成，不事后补写——保证"演示文档里的数字来自程序真实输出"
