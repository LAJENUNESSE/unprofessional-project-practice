# AI 使用说明（AI 协作记录）

本项目为「AI 编程挑战：人机协作开发全流程」训练任务成果。开发全程由 AI 编程助手（ZCode / GLM）辅助完成，本文件按任务步骤记录各阶段的 AI 使用方式、产出与人工介入点，并给出整体的 AI 辅助比例估计。

## 一、协作方式总览

- **工具**：ZCode 命令行编程助手（GLM 模型），具备读写文件、执行命令、运行测试的能力
- **协作模式**：人负责选题决策、需求定义、方案评审、验收测试；AI 负责代码生成、脚手架搭建、测试编写、打包脚本与文档初稿
- **开发过程**：每个模块由人提出明确需求 → AI 生成实现 → 本地运行测试验证 → 发现问题后把报错信息反馈给 AI 修复

## 二、分阶段记录

### 阶段 0：选题与方案设计（人工为主）

- 人工：从「Web 应用 / 数据工具 / 自动化脚本」三个方向中选定数据工具；在候选方案（CSV 清洗报表工具、个人账单分析、数据采集趋势分析、文本词频分析）中确定 **CSV 数据清洗报表工具**
- 人工决策点：界面选 Tkinter（要求能用 PyInstaller 打包 exe）、风险前置策略（先验证打包链路再写功能）
- AI：补充了评分维度分析（功能 40% / 代码质量 30% / AI 协作 30%）与选题建议理由

### 阶段 1：环境搭建（AI 执行，人工验证）

- AI 生成并执行：venv 创建、依赖安装（pandas / matplotlib / chardet / pytest / pyinstaller / tabulate）、PyInstaller 冒烟测试脚本（smoke_test.py）
- **过程中遇到的真实问题（AI 自行定位修复）**：
  1. uv 创建的 venv 不自带 pip → 改用 `ensurepip` 补装
  2. PyPI 直连超时 → 切换清华镜像源
  3. GBK 样例文件用 iconv 转换失败（¥ 符号不在 GBK 兼容集）→ 改用 Python 生成
- 产出：Python 3.14 环境下 tkinter + pandas 3.0 + matplotlib + PyInstaller 6.22 全链路验证通过

### 阶段 2：核心逻辑与测试（AI 生成 ≈95%）

- AI 一次性生成 5 个核心模块（loader / inspector / cleaner / stats / report）与 19 个单元测试
- **人工介入点**：
  1. 测试初跑 3 个失败——定位为测试夹具（fixture）中"重复行"数据不完全相同（城市列带空格差异），人工确认是测试数据构造错误而非实现错误，AI 修正夹具
  2. 人工发现示例数据"重复行"因订单号不同去重无效果，要求 AI 修正样例（体现人验收数据、AI 改数据）

### 阶段 3：GUI 开发（AI 生成 ≈90%）

- AI 生成主窗口 app.py、表格视图 table_view.py、图表面板 charts_panel.py
- **过程中遇到的真实问题（AI 自行定位修复）**：
  1. 同一容器混用 pack/grid 几何管理器导致 TclError → 统一为 grid
  2. matplotlib 中文乱码风险 → 预置 Microsoft YaHei 字体配置与负号修复
  3. 类属性共享列表等不规范写法 → 人工指出后 AI 重构为实例属性
- 无头脚本验证 GUI 构建与数据刷新链路，真机启动截图确认界面正常

### 阶段 4：打包与文档（AI 执行 ≈95%）

- AI 生成 launcher.py、PyInstaller 打包命令并执行；生成 README、项目报告、本说明文档

## 三、AI 辅助比例估计

| 阶段 | AI 产出占比 | 说明 |
| --- | --- | --- |
| 需求与方案 | ~20% | 选题、界面形态、打包要求均由人工决策 |
| 环境搭建 | ~90% | 命令全部由 AI 生成执行，人工只验收结果 |
| 核心逻辑 | ~95% | 代码与测试由 AI 生成，人工负责验收用例合理性 |
| GUI | ~90% | AI 生成，人工提出 1 处重构与验收截图 |
| 打包与文档 | ~95% | AI 生成并执行，人工审阅 |
| **整体** | **约 85%~90%** | 人工主要贡献在决策、验收与纠偏 |

## 四、人机协作效率的观察与体会

1. **风险前置收益最大**：开发前先让 AI 做一次 PyInstaller 冒烟打包，把"Python 3.14 是否兼容"这一最大不确定项在写第一行业务代码前排除，避免了返工
2. **AI 对"报错驱动调试"响应极快**：几何管理器冲突、编码转换失败等问题，把 traceback 交给 AI 一轮即修复
3. **人不可替代的环节是验收**：AI 生成的测试全部通过 ≠ 数据符合预期（样例数据"假重复行"问题测试测不出来），需要人工看数据、看界面
4. **明确约束提升 AI 产出质量**：一开始就定死"Tkinter + 打包 exe + 操作日志可追溯"等约束，AI 生成的方案无需大改
